# 06 — Technical Decisions Log

Architecture Decision Records (ADRs) for the choices in this codebase that
are not obvious from reading a single file in isolation — each one trades
off against a real alternative, and reversing it silently would break an
invariant relied on elsewhere in the pipeline.

| ADR | Decision | Rationale | Enforced by |
|---|---|---|---|
| ADR-001 | All network I/O is isolated in `src/acquisition/`. No other layer (spatial, economics, potential, sensitivity, viz) makes a network call. | Replacing a data provider (e.g. GADM → BKG VG250 for Germany) then requires no change to any downstream module. Also makes every downstream stage testable offline once `data/raw/` and `data/boundaries/` are populated. | Hard Rule 5 (root `CLAUDE.md`); every acquisition module exposes `fetch(region, config) -> Path`. `spatial/admin_boundaries.py` was refactored specifically to remove network calls it originally made — see `SPRINT_LOG.md` "Issue 1". |
| ADR-002 | The zero-incentive baseline is hard-coded inside `economics/decomposition.py`'s private `_lcoh_for()` helper (`incentive_value_usd_per_kg=0.0`), not read from `region_cfg.incentives`. Real incentive values are applied exclusively by `economics/incentive_scenarios.py`, calling `calculate_lcoh()` directly. | Fixes a prior bug where Germany's incentive silently contaminated the actual/WACC-swap/inversion-point baseline. Keeping incentive logic entirely out of `_lcoh_for()` — rather than passing `incentive=0` as a caller-supplied default — makes the omission structural, not convention-dependent. | Verified via `inspect.getsource(decomposition._lcoh_for)`; see the verification command in [08_commands_and_reproducibility.md](08_commands_and_reproducibility.md). |
| ADR-003 | `RegionCRS` in `src/core/constants.py` is the single source of truth for coordinate reference systems. No module hardcodes a CRS string. | Prevents silent pixel misalignment between the analysis grid and boundary geometry if a CRS string drifted independently in two places. `spatial/grid_utils.get_analysis_grid()` actively cross-validates `config.regions.<region>.grid_crs` against `RegionCRS.projected_crs_for(region)` and raises `ValueError` on any mismatch, rather than trusting the YAML alone. | Hard Rule 1 (root `CLAUDE.md`); see [04_spatial_methodology.md](04_spatial_methodology.md) for why the CRS is a custom Albers Equal Area Conic per region rather than a UTM/EPSG code. |
| ADR-004 | Every numeric parameter used anywhere in the study lives in `config/scenario_params.yaml`, loaded and validated once via Pydantic (`config/config_loader.py: load_scenario_config()`) before any other module runs. No module reads the YAML directly except `config_loader.py`. | Centralizes every assumption (WACC, CAPEX, TOPSIS weights, thresholds, incentive parameters) in one reviewable, version-controlled, schema-validated location — critical for an academic pipeline where every numeric input must be traceable to a cited source or flagged as a placeholder. Pydantic validators additionally enforce cross-field invariants at load time (e.g. TOPSIS weights sum to 1.0, WACC/CAPEX ranges have min < max) that a raw YAML read would not catch. | Hard Rule 4 (root `CLAUDE.md`); `spatial/_config_helpers.py` is the one exception carve-out — the only place permitted to translate `Region` enum → YAML config key, itself just a thin lookup on the already-validated config object. |
| ADR-005 | Administrative boundaries are read from on-disk GeoJSON (`data/boundaries/{region}.geojson`), written once by `acquisition/admin_boundaries_fetch.py`, rather than re-fetched from IBGE/GADM on every pipeline run. | Enables zero-network execution of every downstream stage (spatial, economics, sensitivity) once boundaries have been fetched once, and makes `spatial/admin_boundaries.py` testable and inspectable without live network dependency. Directly closed a prior architecture violation where `admin_boundaries.py` made its own network requests. | `spatial/admin_boundaries.py`'s `_BOUNDARY_FILES` reads exactly the path `admin_boundaries_fetch.py` writes (this alignment was itself a fix — see `SPRINT_LOG.md`, Stage 3 item 17); CRS is assigned directly via `RegionCRS.projected_crs_for(region)` on read, since the boundary files carry the wrong CRS tag as stored. |
| ADR-006 | `sensitivity_analysis.run_sobol_analysis()`'s Sobol global sensitivity analysis covers exactly 3 parameters (WACC, capacity_factor, renewable CAPEX), not the 5 originally proposed (adding electrolyzer CAPEX, electrolyzer OPEX, and capacity_density) — see [05_economic_model.md](05_economic_model.md#sobol-global-sensitivity-analysis-srcsensitivity) for the full comparison table. | Electrolyzer CAPEX/OPEX have no literature min/max range anywhere in `scenario_params.yaml` (still bare floats); adding an invented `±%` band would violate the same "no arbitrary bounds" principle this feature exists to enforce for the other 3 parameters. capacity_density is structurally excluded, not just missing a range: `calculate_lcoh()`'s signature has no capacity/area/density parameter at all, so its Sobol indices against LCOH would be exactly zero by construction, not merely small — computing them would misleadingly imply a real (near-zero) sensitivity result rather than a structural non-relationship. | `src/economics/lcoh_model.py: calculate_lcoh()`'s parameter list (no capacity/area/density argument, verified by direct inspection); `config_loader.py`'s `ElectrolyzerTechConfig`/`ElectrolyzerSharedConfig` (still `float`, not `RangeParam`) vs. `RenewableTechConfig.capex_range` / `RegionConfig.wacc.range` / `TechRegionParams.capacity_factor` (all already ranges). |
| ADR-007 | `exclusion_mask.create_exclusion_mask()`'s administrative-boundary clip (`_rasterize_boundary()`) is applied by rasterizing the dissolved polygon onto the reference grid and AND-ing it into the existing combined mask (the same point land-use and protected-area masks are already combined), rather than cropping each of the 5 raw criterion rasters individually right after their own load, before reprojection, as originally specified. | The 5 criterion rasters arrive in different native CRSs and go through 2 different reprojection code paths (`data_layers._load_layer()`'s `grid_utils.reproject_and_resample()` for 4 of them, `data_layers.load_slope()`'s own direct warp for the 5th) that each independently compute an output transform — this module's own pre-existing ALIGNMENT NOTE already documents why every mask here is instead built directly on `get_analysis_grid()`'s exact transform/shape and combined via logical AND: it is the only way to guarantee pixel alignment across land-use, protected-area, and (now) boundary masks without a third independent per-raster alignment implementation. Cropping 5 raw rasters individually pre-reprojection would have meant reimplementing that alignment guarantee per-loader, a much larger and riskier change for the same end result (every mask/score that already keys off `create_exclusion_mask()`'s output is unaffected by which layer the AND happens at). | `exclusion_mask.py`'s pre-existing ALIGNMENT NOTE (module docstring) and `_reproject_landuse_to_grid()`/`_rasterize_protected_areas()`, which already established this same pattern for land use and protected areas before this ADR; `_rasterize_boundary()` is a third instance of the identical pattern, not a new one. |
| ADR-008 | Brazil's WACC baselines were raised (8.0%→11.0% solar, 9.0%→12.0% wind) to reflect emerging-market financing costs, but the solar<wind ordering was deliberately **kept**, not reversed to solar>wind as originally requested by a later task. `RegionConfig.onshore_wind_capex_override_usd_per_kw` (new optional field, `None` unless a region sets it) was added so Brazil's onshore wind CAPEX could drop to a competitive-Northeast benchmark (1,300→1,050 USD/kW) without touching Germany's, since `RenewablesConfig` has no region axis. | The task motivating the WACC reversal claimed an "inverted" Brazil wind/solar LCOH relationship needing correction; this was verified false before implementing anything (Brazil wind was already cheaper: 5.61 vs. 6.09 USD/kg under the prior baseline). The requested reversal also contradicted this project's own cited Steffen (2020) basis for solar<wind WACC, used for both regions' existing baselines, with no new citation offered for treating Brazil differently. Raising both values while preserving the ordering achieves the requested "align with emerging-market literature" magnitude increase without introducing a claim inconsistent with the manuscript's own already-written methodology text. The CAPEX override was still implemented as requested (an independently justifiable IRENA/EPE-based change, not tied to the false premise) — resulting in Brazil wind (6.10 USD/kg) remaining cheaper than Brazil solar (7.34 USD/kg), achieved honestly rather than via an unsubstantiated WACC reversal. | `docs/memory/05_economic_model.md`'s WACC-swap and region-specific-CAPEX-override sections; `config_loader.py`'s `RegionConfig.onshore_wind_capex_override_usd_per_kw`; `decomposition.py`'s `_effective_renewable_capex()`, reused by `sensitivity_analysis.py` to prevent cross-module drift. |
| ADR-009 | The single top-level `scenario.active` selector was removed entirely. The pipeline now always executes three COMBINED scenarios (`min`/`baseline`/`max`) in sequence for every region+technology pair, in which WACC, capacity factor, capacity density, and renewable CAPEX all move to their worst-case or best-case extreme SIMULTANEOUSLY, rather than one globally-selected branch per run. WACC was migrated from a scalar (`solar`/`wind` floats) plus one shared `range` tuple into a per-technology `{min, baseline, max}` `RangeParam` (`RegionWaccConfig`), resolved via a NEW `config_loader.resolve_inverted_param()` (WACC's combined-scenario direction is inverted relative to every other `RangeParam`: "min" combined scenario = WACC's own `max` branch, since worse financing means higher, not lower, WACC). The 1D Brazil-only `find_inversion_point()`/`run_inversion_point_scenario_sweep()`/`run_extended_wind_wacc_search()` functions (all in `decomposition.py`) were deleted and replaced by a 2D `WACC_BR x WACC_DE` grid search in the new sibling module `src/economics/competitiveness_frontier.py`, reporting two subsidy-equivalence metrics (WACC-gap closure, direct support) instead of a single inversion WACC. `inversion_search`/`InversionSearchConfig` (confirmed dead config -- nothing ever read `lcoh_target_usd_per_kg`/`search_tolerance`/`max_iterations`) was removed and replaced by `competitiveness_frontier`/`CompetitivenessFrontierConfig` (`wacc_steps`, `parity_tolerance_pct`). | An independent, one-at-a-time treatment of each parameter's uncertainty band (only capacity_factor varied across the old min/baseline/max sweep; WACC and CAPEX were fixed scalars) understates the true worst-case/best-case LCOH envelope, since favourable and unfavourable draws of different parameters would otherwise be free to cancel out within a single "min" or "max" run. Stacking every parameter's worst case simultaneously is the coherent worst-case scenario a reader expects "min" to mean. The 1D inversion search's own single-country framing could not represent Germany's own WACC uncertainty at all; a 2D frontier makes both countries' financing-cost uncertainty visible simultaneously and yields two distinct, more directly policy-actionable numbers (a financing-cost-reform value and a direct-subsidy value) instead of one crossing point. | `config_loader.py`'s `RegionWaccConfig`, `resolve_inverted_param()`, `CompetitivenessFrontierConfig`; `scenario_params.yaml`'s per-technology `wacc:` blocks and `competitiveness_frontier:` block (no more `scenario:` block); `decomposition.py`'s `_tech_wacc()`, `_effective_renewable_capex_for_scenario()`, `_lcoh_for()`'s `scenario` parameter; `src/economics/competitiveness_frontier.py`; `sensitivity_analysis.py`'s `_wacc_sweep_values()`/`_sobol_bounds()`, both fixed to read technology-specific WACC bounds instead of one shared region-wide range (a latent bug this refactor also closed, since solar and wind previously silently sampled WACC from the identical bound in Sobol). |
| ADR-010 | `exclusion_mask.create_exclusion_mask()`'s protected-area rasterization now applies a buffer of `config.thresholds.min_distance_to_protected_area_km` (converted to metres) around each protected-area polygon before rasterizing, via `_rasterize_protected_areas()`'s new `buffer_m` parameter. `max_slope_degrees`, `min_capacity_factor`, and `max_distance_to_grid_km` were removed from `ThresholdsConfig`/`scenario_params.yaml` as confirmed-unused dead configuration (verified by grep: none read by any binary exclusion cutoff, nor by `topsis.py`'s continuous weighted criteria). | `METHODOLOGY.md` §2.3 has always described a "2-kilometre exclusion buffer around protected area boundaries" as part of the study's spatial methodology, but `exclusion_mask.py`'s protected-area rasterization implemented zero buffer until this ADR -- a real gap between the stated methodology and the code, not merely an unresolved design question, flagged across `scenario_params.yaml`, `docs/memory/04_spatial_methodology.md`, and `tests/test_exclusion_mask.py`'s own SCOPE NOTE for multiple prior sessions. The other three threshold keys were never wired into any exclusion logic in this codebase's history (confirmed by direct grep of `src/` for each key) and carried no methodological claim requiring implementation, unlike the buffer -- removing them as dead configuration is a cleanup, not a design change, while implementing the buffer closes a genuine methodology/code mismatch. | `exclusion_mask.py`'s `_rasterize_protected_areas()`/`create_exclusion_mask()`; `config_loader.py`'s trimmed `ThresholdsConfig`; `scenario_params.yaml`'s `thresholds:` block; `tests/test_exclusion_mask.py`'s buffer test cases; `docs/memory/04_spatial_methodology.md`'s RESOLVED note. |
| ADR-011 | `thresholds.min_distance_to_protected_area_km` (ADR-010's uniform 2 km buffer) was split into a per-region value: Brazil keeps 2 km, Germany drops to 500 m. `ThresholdsConfig.min_distance_to_protected_area_km` changed from `float` to a new `ProtectedAreaBufferConfig(BaseModel)` (`brazil: float`, `germany: float`, both validated non-negative). `exclusion_mask.create_exclusion_mask()` resolves the region-specific value via a new `_config_helpers.get_protected_area_buffer_km(region, config)` helper (same `Region` → config-key translation pattern as the existing `get_grid_crs()`), rather than reading the flat field directly. | A uniform 2 km buffer, applied to both regions' protected-area datasets alike, ignored a real difference in protected-area regime: Brazil's federal conservation units (UCs federais) are strict no-use reserves, so the precautionary 2 km buffer remains defensible there, but Germany's dataset is Natura 2000, which permits sustainable renewable-energy development under EU law subject to mitigation -- verified live before this change, a uniform 2 km buffer left Germany at ~25k km² suitable (~60% excluded) out of 63,298 km² total region area, a result inconsistent with actual German RE siting practice (VDMA/BNetzA document wind/solar deployment inside Natura 2000 with appropriate mitigation). Verified live after the split: Germany rose to 45,113 km² suitable (28.7% excluded) at a 500 m buffer, while Brazil's own 1,484,236 km² suitable figure is unchanged (its buffer value didn't change). | `config_loader.py`'s `ProtectedAreaBufferConfig`, trimmed `ThresholdsConfig.min_distance_to_protected_area_km` field type; `scenario_params.yaml`'s per-region `thresholds.min_distance_to_protected_area_km` block; `src/spatial/_config_helpers.py`'s `get_protected_area_buffer_km()`; `exclusion_mask.py`'s `create_exclusion_mask()` call site; `tests/test_exclusion_mask.py`'s `_stub_config()` and `TestProtectedAreaBufferResolution`. |

| ADR-012 | Germany's solar/onshore-wind capacity-factor ranges and renewable CAPEX were updated to Abuzayed & Hartmann (2022) (solar CF 9.2-14.6%, wind CF 19.6-36.5%, solar CAPEX 660 USD/kW, wind CAPEX 1,317 USD/kW, both CAPEX figures converted from EUR at a fixed 1.10 rate); Brazil's onshore wind CF range was separately updated to 30-42% (baseline unchanged at 36%) from IRENA (2024)'s 56% global-high benchmark and MDPI (2025) operational-farm data. Since `RenewablesConfig.solar_pv`/`.onshore_wind` CAPEX have no region axis, updating them for Germany would have silently changed Brazil's solar CAPEX too (Brazil had no solar override before this ADR, unlike onshore wind since ADR-009) -- `RegionConfig` gained `solar_pv_capex_override_usd_per_kw`/`solar_pv_capex_range_override_usd_per_kw` (mirroring the existing onshore-wind override fields), set to Brazil's pre-ADR-012 values (700 USD/kW, [500,1000]) so Brazil's solar CAPEX is bit-for-bit unaffected. `decomposition._effective_renewable_capex()`/`_effective_renewable_capex_for_scenario()` were generalized from an `onshore_wind`-only `if` branch to a `{"solar_pv": ..., "onshore_wind": ...}` field-name lookup so both technologies' overrides resolve through the same single chokepoint. | The task explicitly required updating only Germany's technology parameters (plus Brazil's wind CF from separate literature) while leaving "all other Brazil parameters unchanged," including Brazil solar CAPEX -- but the pipeline's `RenewablesConfig` schema shares one CAPEX value per technology across both regions, so a literal Germany-only YAML edit to `renewables.solar_pv` would have violated that constraint by construction. Adding a symmetric Brazil-only override (the same mechanism already used for onshore wind since ADR-009) resolves this without touching Brazil's actual solar economics, and keeps the override mechanism consistent across both renewable technologies rather than special-casing wind only. Competitiveness-frontier signs (Brazil solar competitive/no subsidy needed; Brazil wind not competitive/subsidy required) were left to emerge from the recomputed baselines rather than forced, per the task's own constraint -- both signs were unchanged, only magnitudes shifted (solar direct support -0.40 -> -0.26 USD/kg; wind +1.95 -> +1.92 USD/kg). | `config_loader.py`'s `RegionConfig.solar_pv_capex_override_usd_per_kw`/`solar_pv_capex_range_override_usd_per_kw`; `scenario_params.yaml`'s `regions.brazil` override fields and `technologies.germany`/`technologies.onshore_wind.brazil`/`renewables` blocks; `decomposition.py`'s `_CAPEX_OVERRIDE_FIELD`/`_CAPEX_RANGE_OVERRIDE_FIELD`; `docs/memory/05_economic_model.md`, `docs/memory/09_methodology_assumptions.md`. |

| ADR-013 | `competitiveness_frontier.py`'s direct-support metric (LCOH_BR - LCOH_DE) is now computed at all three combined scenarios (min/baseline/max, both regions moved to the SAME branch simultaneously) via new `direct_support_by_scenario()`/`direct_support_range()` functions, reported as a range rather than a single baseline number; `summarize_frontier()` prints the requested `[frontier] {tech} direct support range: $min – $max/kg (baseline $base)` line plus a plain-language interpretation (`_interpret_direct_support_range()`), with neither the range's sign nor which endpoint is larger forced in advance. `incentive_scenarios.py`'s REHIDRO/IPCEI scenario functions are retained unchanged (still report LCOH at the configured, permanently-zeroed credit) but are supplemented by a new `summarize_incentive_equivalence()`, reusing `direct_support_range()`'s baseline gap rather than re-deriving or inventing a number, replacing the earlier practice of modeling REHIDRO/IPCEI as flat per-kg placeholder credits (1.00 USD/kg Brazil, 2.00-4.50 EUR/kg Germany) with an honest description of what a hypothetical credit would need to be, contrasted against the real (non-per-kg) programme designs. | Closer examination of REHIDRO (a CAPEX-side tax suspension, not a production subsidy) and Germany's IPCEI/H2Global/CCfD (investment and offtake instruments, not per-kg credits) found that neither region's real incentive landscape resembles a flat per-kilogram production credit at all -- continuing to model either as one, even as a clearly labeled placeholder, risked being read as evidence such a credit exists or is imminent. A single baseline-only direct-support number also understated how much the Brazil-Germany LCOH gap moves across the study's own literature-reported uncertainty ranges: solar's baseline advantage (-0.26 USD/kg, Brazil cheaper) is not robust across the full min/baseline/max range (+2.92 to -0.90 USD/kg), a materially different finding than the baseline-only figure alone would suggest. Germany's side of the incentive-equivalence message deliberately reports no numeric "$W/kg equivalent" for IPCEI+H2Global+CCfD, since none of the three programmes publishes one and this study's modeled WACC/CAPEX are not decomposed into a policy-attributable share -- inventing one would violate this task's own "do not invent fake incentive values" constraint. | `src/economics/competitiveness_frontier.py`'s `direct_support_by_scenario()`, `_interpret_direct_support_range()`, `direct_support_range()`, and `summarize_frontier()`'s updated return dict; `src/economics/incentive_scenarios.py`'s `summarize_incentive_equivalence()` and updated `run_all_incentive_scenarios()`; `scenario_params.yaml`'s `regions.<brazil\|germany>.incentives` comments; `METHODOLOGY.md` section 2.8 (rewritten) and 2.8.1 (new); `docs/memory/05_economic_model.md`'s REHIDRO/IPCEI section (rewritten). |

## Adding a new ADR

When a future decision trades off against a real alternative in a way not
obvious from the code alone — a new data provider, a new persistence
format, a new config-validation rule — add a row here in the same unit of
work that makes the change, per the root `CLAUDE.md` documentation-update
rule. Number sequentially (ADR-006, ...); do not renumber or delete
existing entries even if later superseded — add a new ADR noting the
supersession instead.
